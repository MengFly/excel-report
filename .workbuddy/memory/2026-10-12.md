# 2026-10-12

## javadoc 打包失败诊断（`mvn package` → `maven-javadoc-plugin:3.2.0:jar`）

- 现象：attach-javadocs 阶段 fail，`javadoc.exe` exit 1，**5 错误 / 7 警告**。
- 真因（5 个 error，都是 doclint 默认开启的组）：
  - **3 × `reference`**：`WebCell:13` 的 `{@link WebCellContent#getKind()}`、`WebCellContent:10` 的 `{@link #getKind()}`、
    `WebCellRange:11` 的 `{@link WebExcel#getCells()}` —— 三个方法都由 Lombok `@Getter` 编译期生成，javadoc 直接读源码看不到。
  - **2 × `html`**：`ReportContext:171/182` 注释里的裸 `->` 被判为「'>' 的用法错误」（javadoc 注释按 HTML 解析）。
- 7 个 warning（不 fail）：`TemplateFactory:22` 缺 `@return`、`BridgeExporter:16` 缺 `@param <T>`、`ExcelReport:71` 缺 `@return`、
  `未知的枚举常量 When.MAYBE`（spring `@Nullable` 的元注解引用 JSR-305 的 `javax.annotation.meta.When`，jsr305 不在依赖里）。
- **实测：加 `-Xdoclint:none` 后 exit 0**（html / reference 的 error 降级为 warning）。⇒ jsr305 与缺 tag 都只是 warning，不会 fail。
- **doclint 检查范围实测**：只检查默认 visibility（protected 及以上）的类/方法注释；
  private 字段注释（WebExcel / WebCell / WebTextRun 等）与包内私有类（`WebStyleNormalizer`）**不检查** —— 所以同样的 `->` 写法没报错。
- 探针：`target/probe/{ProbeArrow,ProbeRef}.java`，直接用 `D:/Java/jdk1.8.0_231/bin/javadoc.exe -encoding UTF-8` 跑（`mvn clean` 即清）。
- 另注：`mvn -o javadoc:javadoc` 的输出是 GBK，需 `iconv -f GBK -t UTF-8` 才能读。
