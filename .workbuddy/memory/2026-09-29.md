## 评估：SheetStyles 是否可与 CellStyles 合并（2026-09-29，仅判断未改代码）

- 结论：**结构上已同形（四.2 之后），可以合并；但正确粒度是"抽公共注册表实现、保留两个门面"，不要把两个 `styleMap` 并成一个。**
- 支撑数据（脚本比对）：
  - `CellStyles` 33 个 key ↔ XSD `Style` 31 个子元素；`SheetStyles` 27 ↔ XSD `SheetStyle` 27，**双向差集均为空**（SheetStyles 侧完全 1:1）。
  - 两类 key **交集为空**（33+27=60 并集），XSD 的 `Style` 与 `SheetStyle` 子元素交集也为空 ⇒ 天然互斥命名空间。
  - 两文件**完全相同的非空行 21 行**（219 行 / 116 行），其中真正的管道重复约 9 行：`styleMap`、`DEFAULT_STYLE`、`getStyleKey`、两个 `register`。
- 不建议并成一个 map 的理由：① 会丢掉 XSD 两套命名空间的运行期镜像 —— `<style>` 里写 sheet key 从"查不到丢弃"变成"进 StyleMap 后被类型过滤丢弃"，
  行为看似一致但 `StyleMap` 多一个 key ⇒ 改变 `StyleMap.equals` ⇒ 影响 `cellStylePool`/`fontPool` 池 key（多出冗余 CellStyle/Font，最难排查的那种差异）；
  ② `DEFAULT_STYLE` **不能合并**（cell 默认 20 项 vs sheet 默认 `defaultRowHeight=20f`，`ExcelReport:60`/`:63` 分别消费，方向不能互串）；
  ③ `initSheetStyle`（无类型过滤、直接 apply）与 `createCellStyle`/`createFont`（先过滤再 apply）的语义差不会因合并注册表而消失。
- **顺带发现**：XSD `Style` 缺 `fillBackgroundColor`（XSD 只有 `fillForegroundColor`:462），而 `CellStyles` 有该 key ⇒
  模板写 `fillBackgroundColor` 属"能跑但不合规"（框架运行期不校验 XSD），正是"二.2 按 XSD 校验"能抓到的一类问题。`preferredSize` 则是框架内部 key，不在 XSD 内属正常。

本轮为写 skill 而**新核实的框架事实**（此前未记录，值得留存）：

- **`<container>` 只能有一个元素子节点**：`ReportTemplate.buildTemplateNodeTree` 执行 `XmlUtil.getElements(element,null).get(0)`，多写的兄弟节点**静默丢弃**；空 container ⇒ IndexOutOfBounds。XSD 的 `ContainerGroupContainer` 是 `xs:choice maxOccurs=unbounded`，所以「XSD 合规」≠「运行期正确」。
- **`for` 冒号缺失 = 静默单次渲染**（`ForExpression` 构造时 `firstIndex <= 0` 就把 arg1/arg2 置 null，`process` 回退 `dataConsumer.accept(context)` 一次）。`for` 只挂在 `AttrForeach`（VLayout/HLayout/GridLayout + Chart 的 valueAxis/3dValueAxis）。
- **颜色是两套枚举**：单元格侧 `ColorStyleKey` 用 `HSSFColorPredefined`（`getDefinitionColor` 走 `EnumUtil`），图表侧 `XDDFColorHelper` 用 XDDF `PresetColor`。名字不在枚举里**静默回退**（单元格黑 / 图表绿）。`#RRGGBB` 是唯一两套都认的写法。
- **`Table`/`List` 的正数 `size` 无效**：`WeightSizeHelper.getChildSize` 只在 `preferredSize < 0` 时返回 -1，否则返回 `child.getSize()`（Table=GridLayout 自算、List=按数据）。⇒ 撑满只能写 `-1`。
- **`TableComponentNew` 内部就是 `GridLayout(count=列数, horizontal)`**，表头是 `TextComponent`；表头样式走 `column@style`（叠加 `TableColumn` 构造器里的 fontBold13/居中），数据走 `column@dataStyle`。`headerVisible=false` 时 `Table` 的 `style` 也不作用于表头。
- **`include` 的子模板拿到全新 DataContext**（`IncludeParser` new 了一个 `DataContext`），**不继承父上下文** ⇒ 参数必须显式传。
- **`TemplateManager` 有模板解析缓存**，改模板不生效先 `clearCache()`。
- 其余已核对：`RichText.isRichText` 要求 `<html>` 开头 `</html>` 结尾；`ComposeExpression` 让多片段表达式退化为 String（单片段才保留数字类型）；`TemplateFactory.checkId` 自动补 `.xml`；`SheetStyles.forceFormulaRecalculation` 注册为 Boolean 而 XSD 写 `xs:integer`（不一致）。
