# 静默陷阱清单 & 交付 Checklist

框架**不做严格校验**，写错基本不报错，只表现为「样式不生效 / 组件凭空消失 / 格子变形」。
下面按「症状 → 根因 → 规避」列出。

## 一、静默失效（按症状索引）

| 症状 | 根因 | 规避 |
|---|---|---|
| 页面里只出现第一个组件，后面的都没了 | `<container>` 下有多个根组件，只读取第一个 | 用 `<VLayout>` 包一层 |
| 某个样式整段不生效 | ① 样式 key 拼错 / 大小写错 ② 样式 id 不存在 ③ 内联 JSON 里 value 含未加引号的 `${}`，导致整段解析失败 | 跑 `scripts/check_template.py`；含 `${}` 的 value 加引号 |
| 颜色不对（黑 / 默认绿） | 单元格与图表用的是**两套颜色名**，用错那套会回退 | 统一 `#RRGGBB`；或对照 `template-spec.md §4.2` 的两份名单 |
| 边框全没了 / 想去掉边框却还在 | 默认四边 `thin`，且**外层容器的样式会继承到子组件** | 显式 `borderXxx=none`，并注意外层容器样式的影响面 |
| 图表凭空消失 | 没写数据节点（`<ChartData>` / `<Chart3dData>` / `<PieData>`），或标签名拼错 | 数据节点必须写且只能有一个，用检查脚本兜底 |
| 图表的某个系列没画出来 | 该 `<data>` 既没给 `dataList` 也没给 `address`，或数据列表为空 | 检查表达式是否取到了非空列表 |
| `for` 循环只渲染了一次 | `for` 值里少了 `:` | 写 `for="item,index: ${list}"` |
| 数字变成了文本（左上角绿三角 / 无法参与计算） | `text` 里有多段（`${a}${b}`）会拼成字符串，或字面量里带了单位 | 数字单独一个 `${num}`，单位另起一个 `Text` 单元格 |
| 列宽被撑得很宽 | 同一列多个带 `width:auto` 的单元格取最大值，长文本赢了 | 只给需要自适应的列设 `auto`，其余给固定数字 |
| 列宽变成很窄的垃圾值 | 在只做合并、不写内容的组件（`Span` / `Chart`）上写了 `width:auto` | 去掉这些组件的 `width:auto` |
| 行高全都不生效 / 都是默认值 | `sheetStyle.defaultRowHeight` 只对「没单独设 `height` 的行」生效 | 检查是不是某处 `height` 覆盖了整个区域 |
| 改了模板文件没反应 | 模板解析结果有缓存 | 清理缓存 / 重新部署后再验证 |
| 单元格里出现了 `${...}` 原文 | 表达式写错，解析失败后按字面量输出（不报错） | 检查 `${}` 内的语法 |
| Sheet 名和预期不一致 | Sheet 名由导出时的 name 参数决定（与 `template@name` 无关）；重名会自动加 `_1` | 用导出时的 name 参数控制 |
| `include` 进来的子模板取不到数据 | 子模板拿到的是**全新的参数集合**，不继承父模板变量 | 在 `<include>` 上把参数全部显式传进去 |
| 打印分页没效果 | 分页标签放在第 0 行会算出负的行号 | 把它放在有内容的行之后 |

## 二、语义容易踩错的点

- **适用范围**：框架定位是**复杂报表**（合并区 / 多列布局 / 图表 / 图片精确定位 / 精确宽高）。
  **大数据量（万行以上）导出不属于它的适用范围**，应改走 POI SXSSF / EasyExcel(FastExcel) / 流式 CSV，不要在模板层硬扛。
- **`Table` / `List` 的正数 `size` 无效**，只有 `-1` 生效。
- **`column@id` 取值**：Java 对象按**字段名**取（不是 getter 名）；Map 按 key 取；嵌套用 `.`（`id="user.name"`）。
  字段名对不上不会报错，只会渲染成空 ⇒ 交付前用真实数据跑一遍最稳。
- **样式继承**：父容器的 `style` 会**继承**到子组件。写「只给表头加底色」时，不要把 `fillForegroundColor` 写在
  `<Table>` 或外层 `VLayout` 上。
- **`alignPolicy` 只影响交叉轴**（VLayout 管水平、HLayout 管垂直），不改变主轴堆叠顺序。
- **`Table` 不擅长不规则合并表头**：它每行的格子数固定 = 各 `columnSpan` 之和。需要不规则合并就
  `headerVisible="false"` 后自己用 `Text` 拼。
- **`Span` 只合并不写值**；要写值用 `Text`（`Text` 本身也会合并）。
- **`Image` 的尺寸是「单元格区域」**，最终像素依赖列宽/行高 ⇒ 需要精确像素排版时先固定列宽/行高。
- **不要指望「写法不同但效果相同」的样式能复用同一份格式**：写法不同就是不同的样式定义。

## 三、交付前 Checklist

模板层：

- [ ] `<container>` 下**恰好 1 个**根组件
- [ ] `python scripts/check_template.py <file>` 的 ERROR 全部清零，WARN 逐条确认
- [ ] 所有 `style="id..."` 引用的 id 都在 `<styles>` 里定义过
- [ ] 所有样式 key 用词正确、大小写正确
- [ ] 颜色统一 `#RRGGBB`（或确认用了对应名单里的名字）
- [ ] 中文报表显式设置了 `fontName`
- [ ] 数字列用 `dataFormat` 交给 Excel 格式化，而不是在 Java 侧拼字符串
- [ ] 需要撑满的组件写了 `-1`，而不是正数
- [ ] `for` 都带 `:`；`if` 里的表达式在数据缺失时有兜底（`${x == null ? ... : ...}`）
- [ ] 图表有且只有一个数据节点；饼图 `varyColors="true"`
- [ ] 多级表头的表头块宽度之和，等于下方表格各列 `columnSpan` 之和

数据层：

- [ ] 每个 `column@id` / `${expr}` 引用到的字段，都在用户数据里真实存在（名称、嵌套层级、大小写一致）
- [ ] `dataList` 表达式的结果确实是列表 / 数组（不是单个对象、也不是 null）
- [ ] **未修改用户的任何数据接口与数据结构**；若有必须改的地方，已在动手前与用户确认
- [ ] 空数据 / null 字段场景不会让模板报错

调用层：

- [ ] 模板放在可加载的位置，id 与调用处一致（可省 `.xml`）
- [ ] 多 Sheet 场景确认每次导出的 name 不重复
- [ ] 改模板后已清理模板缓存 / 重新部署
