## 排查外部模板 WarningDayReport.xml 的合并区重叠报错（只排查，未改任何文件）

- 现象：`IllegalStateException: Cannot add merged region A114:AE114 ... overlaps ... (A110:AE124)`，
  来自 `D:\job\b_project\b_backend\portal\src\main\resources\excel\WarningDayReport.xml` +
  预览参数 `.idea\excel-report-preview\...\WarningDayReport.json`（用户口径："加三个图片列表就报错，去掉就正常"）。
- **根因**：三个图片循环包裹层写的是 `<VLayout size="-1,-1" for="img: ...">`。
  `size` 的高度 `-1` = **弹性（按权重分父级剩余高度）**，不是内容自适应。父级把剩余高度按等权重三等分
  → 37/37/38 行；而三组内容实际是 32/48/32 行（条数 × (1 行标题 + 15 行图片)）。
  3 条那组只分到 37 行 → 子元素顺序排下去溢出 11 行 → 压到下一个兄弟节点 → 两张合并区相交 → POI 抛异常。
  ⇒ 触发条件是**三组列表条数不等**（2/3/2 崩、2/2/2 正常、4/3/3 崩），与"有没有图片"无关。
- 定位手段：`target/probe/` 单文件探针（`Probe.java` 走 render→onMeasure→onLayout 打印每个组件矩形并两两判交；
  `ExportProbe.java` 走真实 POI 导出链打印异常/合并区）。原模板精确复现用户那条错误信息。
- **推荐修复**：去掉包裹层的 `size="-1,-1"`，并把循环体内 `Text`/`Image` 宽度写成 `31`（整表 A..AE）。
  ⚠️ 只删 `size` 不动子元素会让包裹层宽度塌成 0（VLayout 自然宽度 = `max(0, 子宽度)`，`-1` 子元素按 0 计）
  ⇒ 图片变 0 宽。修复后 2/3/2 与 4/3/3 均导出成功、合并区 242 个、行区间连续。
  → `target/probe/fixed-WarningDayReport.xml`（保留原 CRLF）、`target/probe/diagnosis.md`（排查报告）。
- 备选（不推荐）：高度写死 `size="-1,32"/"-1,48"/"-1,32"`，条数一变就复发。
- 框架侧健壮性缺口（供后续参考，未提优化项）：① 弹性高度等权重均分，分配值 < 内容高度时静默溢出、
  到 POI 合并阶段才崩，错误信息与模板位置无关；② VLayout 省略 `size` 时宽度会因 `max(0,-1)` 塌成 0。

  —— 001 高（模板 `size="-1,-1"`，含完整复现矩阵）、002 高（VLayout 弹性溢出无告警）、003 中（省略 `size` 宽度塌陷）。
