## V1.6.0

> 本次发布包含**破坏性变更**，升级前请先阅读第 5 节。

### 1. `[feat]` 模板校验：让"能跑但没生效"的模板显式暴露

框架长期是"静默"的：标签、属性、样式 key 写错不会报错，只是被丢弃或忽略；
`for` 忘了写变量绑定则整段只渲染一次。这类问题在导出结果上表现为"少了一部分内容"，
排查起来要翻模板、翻源码。

现在每次构造 `ReportTemplate` 都会自动做一次校验，问题以 `ValidationIssue` 列表的形式返回：

```java
ReportTemplate template = new ReportTemplate(stream);

// 取本次校验结果
List<ValidationIssue> issues = template.validate();
for (ValidationIssue issue : issues) {
    System.out.println(issue);   // [ERROR] style.undefined-id @ /template/container/VLayout/Text[2]@style: ...
}

// 是否有会导致行为不符预期的问题
boolean broken = template.hasErrors();
```

`ValidationIssue` 包含 `level`、`ruleId`、`path`（出问题的节点路径）、`message` 四项信息，
其中 `level` 分两级：

| Level | 含义 |
| --- | --- |
| `ERROR` | 会导致模板行为与预期不符：内容被静默丢弃、静默回退，或只渲染了一部分 |
| `WARN` | 多半不是本意，但运行期有确定的兜底行为（例如颜色名不认识时回退成黑色） |

校验分两层，互为补充：

1. **结构层**：按框架内置的 XSD 校验标签名 / 属性名 / 样式 key / 枚举取值，覆盖"名字写错"这一类问题
   （需要模板根节点声明了本版本的默认命名空间，否则这一层会跳过并给出 WARN 提示）；
2. **语义层**：XSD 结构上表达不了、只能靠交叉引用或运行期语义判断的问题 ——
   样式 id 是否已定义、`<container>` 是否恰好 1 个根组件、`style` 内联 JSON 写法与 key、样式值能否转换成功、
   颜色名是否会回退、`for` 是否带变量绑定。

### 2. `[feat]` 严格模式：开发期 / CI 直接中断

默认（宽松）模式下校验不影响渲染，问题只在第一次渲染时汇总成一条 WARN 日志。
需要"发现错误就中断"时打开严格模式：

```java
// 建议只在开发期或 CI 打开，生产环境保持默认的宽松模式
TemplateManager.getInstance().setStrict(true);
```

打开后，`TemplateManager#getTemplate(String)` 在模板存在 ERROR 级问题时抛 `TemplateValidationException`，
异常消息里会列出前 10 条问题，完整清单可通过 `getIssues()` 获取：

```java
try {
    ReportTemplate template = TemplateManager.getInstance().getTemplate("TestTemplate");
} catch (TemplateValidationException e) {
    // e.getIssues() 为完整问题清单
    throw e;
}
```

严格模式的判定在缓存之外进行，所以运行期随时打开都生效，已缓存的模板同样会被拦住。

### 3. `[feat]` 模板解析缓存

`TemplateManager#getTemplate(String)` 现在带缓存，同一个模板 id 只解析一次
（解析模板本身包含 XSD 校验与建树，重复解析没有必要）：

```java
TemplateManager manager = TemplateManager.getInstance();
ReportTemplate a = manager.getTemplate("TestTemplate");
ReportTemplate b = manager.getTemplate("TestTemplate");   // 同一个实例

// 模板文件在运行期发生变化时（例如开发期热更新），清缓存后可重新解析
manager.clearCache("TestTemplate");
manager.clearCache();   // 清全部
```

### 4. `[perf]` 性能优化

| 优化项 | 说明 |
| --- | --- |
| 表达式缓存全局共享 | 表达式解析结果由每次解析各存一份改为全局共享，模板渲染时不再重复解析表达式 |
| 样式链重构 | 精简 StyleChain 的样式装配过程 |
| auto 宽高延迟计算 | `width/height=auto` 的自动宽高计算从"渲染过程中反复算"改为"组件终态时统一算一次"，实测计算量约减少一半 |

### 5. ⚠️ 破坏性变更

#### 5.1 包名修正

`io.github.mengfly.excel.report.template.exepression` 包名拼写有误，已更名为：

```
io.github.mengfly.excel.report.template.expression
```

引用该包下类型（`ExpressionHelper`、`TemplateExpression` 及各 `process` 下的表达式实现）的代码需要同步修改 import。

#### 5.2 样式系统重构

样式 key 的注册方式由"传 setter 方法名 + 反射调用"改为"传函数式应用器"，注册即校验签名：

```java
// 旧写法
public static final StyleKey<Boolean> wrapText = register("wrapText", "setWrapText", Boolean.class);

// 新写法
public static final StyleKey<Boolean> wrapText =
        register("wrapText", CellStyle.class, Boolean.class, CellStyle::setWrapText);
```

同时：

- 新增 `StyleRegistry`（样式 key 的登记与查找）与 `StyleApplier`（样式应用器）；
- `CellStyles` / `SheetStyles` 的样式应用入口统一为 `initStyle(target, styleMap)`，
  目标对象由调用方创建（如 `workbook.createCellStyle()` / `workbook.createFont()`）；
  原 `CellStyles#createCellStyle`、`CellStyles#createFont`、`SheetStyles#initSheetStyle` 已移除；
- 移除 `CellWidthHeightKey`（不再需要专门的宽高 key）；
- 继承 `StyleKey` / `NoOpStyleKey` 自定义样式 key 时，构造参数需要按新签名调整。

#### 5.3 其他更名

| 变更前 | 变更后 |
| --- | --- |
| `ContainerTreeNode#getSyleMap()` | `ContainerTreeNode#getStyleMap()` |
| `ReportTemplate#getTemplateManager()` / `setTemplateManager(...)` | 已移除（模板不再持有 `TemplateManager`） |

### 6. 修复

1. `[fix]` 修复同名 Sheet / 匿名 Sheet 超过 2 个时报
   `IllegalArgumentException: The workbook already contains a sheet named 'X'` 的问题；
   现在以原始名称为基数依次追加序号，且生成的名称被占用时继续向后查找；
2. `[fix]` 修复网络图片加载线程可能无限阻塞的问题；
3. `[fix]` 修复行高默认值失效的问题；
4. `[fix]` 修复模板 XSD 的语法错误，并补充单元格样式 key `fillBackgroundColor`；
5. `[fix]` 修复枚举名称替换的正则错误。
