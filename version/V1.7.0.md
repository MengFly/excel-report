## V1.7.0

> 本次发布包含若干**导出结果会变化**的行为变更，升级前请先阅读第 5 节。

### 1. `[feat]` 表达式根对象回落

以前模板里的变量只能从 `DataContext` 这个 map 里取，想用业务对象就得先把字段一个个摊平：

```java
Map<String, Object> data = new HashMap<>();
data.put("userName", user.getName());
data.put("userAge", user.getAge());
ExcelReport report = ExcelReport.getInstance();
report.exportTemplate(template, "sheet1", data);
```

现在可以把整个对象作为"根对象"传入。**map 里取不到的变量与方法，会继续在根对象上按属性 / getter / 方法解析**：

```java
DataContext context = DataContext.builder()
        .put("title", "员工信息")     // map 里的键优先级更高
        .root(user)                  // 取不到就回落到 user
        .build();
report.exportTemplate(template, "sheet1", context);
```

```xml
<Text>${title}</Text>
<Text>${userName}</Text>      <!-- 等价于 user.getName() -->
<Text>${greet('Tom')}</Text>  <!-- 顶层方法调用也会先在根对象上找 -->
```

几个约定：

- **查找顺序是"map → 根对象"**：同名键以 map 为准，适合用 map 覆盖个别字段；
- 根对象可以是任意 POJO（按 getter 解析），也可以是 `Map`（按 key 解析）；
- 子上下文（`for` 循环体等）自动继承根对象，循环内除循环变量外的查找行为与父上下文一致；
- 未设置根对象时行为与之前完全一致。

### 2. `[feat]` 并发渲染与渲染失败可定位

**同一模板实例可被多线程并发渲染。** 此前 `TemplateManager` 缓存模板后，多线程同时渲染同一实例会在 JDK 8 的 DOM 惰性缓存上产生竞态，
表现为"报表缺块但看起来正常"——这正是最难排查的一类问题。现在渲染阶段按模板实例串行，不同模板之间互不阻塞，POI 导出阶段不受锁影响。

**渲染失败不再静默丢掉整块内容。** 出错的处理粒度从"父容器整块"收敛到"出错节点本身"：

- 只跳过出错的节点，兄弟节点照常输出；
- 告警里带节点标签链与出错的表达式，例如 `row[size=-1,20] > cell[size=-1,-1]`；
- `for` 循环里同一节点反复失败时，一次导出只告警一次。

```text
WARN 渲染组件失败，跳过该节点：root[size=-1,-1] > vl[size=31,-1] > text[size=20,1]；表达式：${item.name}
```

拿节点路径到模板里搜索就能直接定位，不必再靠翻堆栈猜是哪一个组件。

### 3. 弹性布局：分配更可控，溢出有告警

`WeightSizeHelper` 的分配逻辑做了重写，规则变成三步：

1. 非弹性子节点按声明尺寸固定；
2. 弹性子节点先以**内容尺寸保底**，剩余空间按 `weight` 分配；
3. 空间不够时按各自内容尺寸**等比压缩**（最小 1），不再按旧顺序继续往后排、越界挤入兄弟节点的行 / 列区域。

分配在构造期一次算完，`distributionSize` 可重复调用并返回同一结果（旧实现每次调用都会继续扣减剩余空间）。

同时新增溢出告警：当弹性子节点实际分配小于内容需要时，导出过程会打出 WARN，点名节点路径、分配值、内容值与父容器可用尺寸。
此前这种情况没有告警，一直拖到 POI 写合并区才抛 `IllegalStateException`，而那个异常只有单元格坐标，很难反推模板。

### 4. 其他修复

| 问题 | 现在的行为 |
| --- | --- |
| `for` 表达式求值为 `null` / 非集合 / 求值异常时多渲染一遍循环体 | 与空列表一致：跳过循环体，只留一条告警；不再出现多出的空白行与无关报错 |
| 列宽超过 Excel 上限 255 字符导致导出直接失败 | 先钳制到 1~255 字符再写入，并告警带列号，整份报表能正常保存 |
| `List` 纵向排列时表头不应用 `header` 样式 | 与横向排列一致，叠加 `header` 样式 |
| `VLayout` / `HLayout` 省略 `size` 时不能继承父级可用尺寸 | 子节点全为弹性时自身尺寸返回 -1，由父级可用尺寸决定；不再挤成 1 行 / 1 列 |
| 图片按区域适配纵向被拉伸 | 区域高度改用像素口径（96 DPI 下 `1 pt = 4/3 px`），与图片像素、列宽像素统一量纲 |
| 图片 `padding` 横向折算偏大 | 横向改用 `EMU_PER_PIXEL`（原为 `EMU_PER_POINT`，2px 会渲染成 2.67px） |

### 5. ⚠️ 行为变更（编译器发现不了）

| 变更 | 影响面与应对 |
| --- | --- |
| 弹性布局尺寸分配规则变化 | 存量模板中弹性子节点的实际尺寸可能与之前不同。渲染后看是否有新的"布局内容溢出"告警；有则调大对应节点的 `size` |
| 省略 `size` 的 `VLayout` / `HLayout` 继承父级尺寸 | 原本被视为"肯定 0 尺寸"的嵌套布局现在会铺满父级可用空间 |
| `for` 求值为 `null` 时不渲染循环体 | 原本会多输出一行（或一段内容）的模板，导出后少这一块 |
| 列宽超过 255 字符的列按 255 写入 | 原本这类模板导出会直接抛异常 |
| `ExcelCellSpan#cellSpanDimension()` 高度单位由磅改为像素 | `CellUtils#scaleCell` 不再按行 / 列区分单位（`isRow` 仅为签名兼容保留）；外部若把该返回值当磅用，需自行换算 |
| `FIT_START` / `FIT_END` / `CENTER` 的图片尺寸变化 | 纵向回落到正确比例；`FIT_XY` 不受影响 |

### 6. 下游影响

- 根对象回落、并发渲染、判断告警都属新增能力；不设置 `root`、单线程渲染的项目，调用方式与 1.6.1 完全一致；
- 受影响的存量场景集中在布局尺寸（第 5 节前两行）与图片适配；升级后建议先跑一遍已有模板，确认导出结果与告警；
- 依赖本框架做预览的下游项目（例如 IDEA 插件）升级依赖版本后，模板无需改动。
