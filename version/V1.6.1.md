## V1.6.1

> 本次发布包含**破坏性变更**，升级前请先阅读第 3 节。

### 1. `[feat]` 报表转前端 JSON

以往导出结果只落在 `XSSFSheet` 里，前端拿不到可传输的结构。现在可以把渲染完成的组件树反推成一张
**扁平单元格网格**：每个单元格带行列与合并跨度、归一化后的样式、内容，外加列宽与行高，
前端按网格铺开即可还原一份"带样式的表格"。

```java
import cn.hutool.json.JSONUtil;
import io.github.mengfly.excel.report.bridge.web.WebExcel;
import io.github.mengfly.excel.report.bridge.web.WebJsonExporter;
import io.github.mengfly.excel.report.excel.ExportResult;

// 导出（与导出 Excel 是同一条链路）
ExportResult result = report.exportTemplate(template, "sheet1", context);

// 转成前端可回显的结构
WebExcel webExcel = WebJsonExporter.instance.export(result);

// 序列化：框架不做这一步，用项目里已有的 JSON 库即可（hutool / Jackson / Gson 都能直接序列化）
String json = JSONUtil.toJsonStr(webExcel);
```

产物示意（字段裁剪过，实际还有 `sheetStyle`、`columnWidths`、`rowHeights` 等）：

```json
{
  "sheetName": "sheet1",
  "rowCount": 3,
  "colCount": 4,
  "cells": [
    {
      "row": 0,
      "col": 0,
      "rowSpan": 1,
      "colSpan": 1,
      "type": "Text",
      "style": {"alignHorizontal": "center", "fontBold": true},
      "content": {
        "value": "销售额",
        "richText": [],
        "kind": "text"
      }
    }
  ]
}
```

几个约定：

- **内容种类看 `content.kind`**：`text` / `image` / `chart`，前端据此分发；`Span` 这类只定义合并区域、
  没有内容的单元格 `content` 为 `null`；
- **样式 key 与模板样式 key 同名**，值已归一化：颜色为 `#RRGGBB`、枚举为小写名、布尔与数字保持原生类型；
- **`type` 是模板标签名**（如 `Text` / `Image` / `Chart`），手工编码构造的组件没有模板信息时取组件类简名；
- **`columnWidths` / `rowHeights` 只含显式设置过宽高的列与行**（含 `auto` 的实测结果），
  其余列行用 `sheetStyle` 里的 `defaultColumnWidth` / `defaultRowHeight` 兜底；
- **图表引用单元格区域时**（`valueType="address"`）输出的是 `reference`（四至坐标），
  由前端从 `cells` 网格里自行取值；
- **必须在 `export*` 之后调用**：样式与宽高是导出过程中算出来的，提前调用只会得到空样式。

另外新增 `TextStructExporter`，把组件树输出成带缩进的文本结构（`HLayout[...] { Text[...] }`），
排查布局问题时比翻日志直观：

```java
String structure = TextStructExporter.instance.export(result);
```

### 2. `[feat]` 导出结果与完整样式

导出入口现在会返回 `ExportResult`，它是"这一次导出的结果"：既有渲染后的组件树，也有导出上下文。

```java
ExportResult result = report.exportTemplate(template, "sheet1", context);

Container root = result.getContainer();       // 渲染（measure → layout → export）后的组件树根
StyleMap style = root.getFinalStyle();        // 本次导出合并后的完整样式（含从父组件继承的）
```

`getFinalStyle()` 返回的是"祖先链 + 自身"逐层合并后的结果，仅供**导出完成后**读取；
组件未参与导出时返回 `null`。样式继承关系因此可以直接查，不必再沿父链手工拼装。

`ReportContext` 同时开放了本次导出算出的列宽 / 行高与 sheet 级样式，`WebJsonExporter` 正是从这里取尺寸。

### 3. ⚠️ 破坏性变更

#### 3.1 组件包迁移

引用以下类型的代码需要改 import（类名不变）：

| 变更前 | 变更后 |
| --- | --- |
| `component.TextComponent` | `component.text.TextComponent` |
| `component.LinkComponent` | `component.text.LinkComponent` |
| `component.SpanComponent` | `component.text.SpanComponent` |
| `component.chart.AxisType` | `component.chart.axis.AxisType` |
| `component.chart.data.ChartMarker` | `component.chart.component.ChartMarker` |
| `component.chart.data.ChartTitle` | `component.chart.component.ChartTitle` |
| `component.chart.Legend` | `component.chart.component.Legend` |
| `component.chart.data.AxisDataResolver` | `component.chart.data.resolver.AxisDataResolver` |
| `component.chart.data.ValueAxisDataResolver` | `component.chart.data.resolver.ValueAxisDataResolver` |
| `component.chart.data.RelationAxisDataResolver` | `component.chart.data.resolver.RelationAxisDataResolver` |

> 图表轴数据解析拆出了 `data.resolver` 包，坐标轴类型归到 `chart.axis`，标题 / 图例 / 数据标签归到 `chart.component`。

#### 3.2 `TableComponent` 语义替换（不一定能被编译器发现）

`TableComponent` 这个名字**留下来了，实现换了**：

- 原 `TableComponent`：直接用 `dataList` + `columns` 写单元格，自带导出逻辑；
- 新的 `TableComponent`：即原 `TableComponentNew`，内部用 `GridLayout` 承载 `Text` 子组件，导出走标准组件链路。

```java
// 这段代码在 1.6.0 和 1.6.1 都能编译通过，但走的已经是另一套实现
TableComponent table = new TableComponent(dataList, columns);
```

1.6.0 的双参构造 `TableComponent(dataList, columns)` 在新类上同样存在，所以**升级时编译器不会提醒**。会编译失败的是这几处：

```java
new TableComponent();                       // 无参构造已移除
table.setDataList(dataList);                // 字段改为 final，setter 不再生成
table.setColumns(columns);                  // 同上
table.setHeaderHeight(2);                   // 同上
table.setHeaderVisible(false);              // 同上
```

模板里的 `<Table>` 标签自动指向新实现，模板本身不用改。若升级后发现表格的合并方式或样式继承与预期不同，
差异来源就在这里。

#### 3.3 方法移除

| 移除的方法 | 替代做法 |
| --- | --- |
| `Container#print()` | 用 `TextStructExporter` 导出组件树文本 |
| `Layout#print()` | 同上 |
| `Container#getTypeName()` | 用 `getClass().getSimpleName()`；需要模板标签名时读 `templateNode().getTagName()` |

### 4. 下游影响

- 包迁移与方法移除只影响**引用这些类型的代码**；模板文件（XML）不需要改，`<Table>` 等标签仍按原来的写法解析；
- `bridge` 包为纯新增，原有"导出 Excel"的调用方式与 1.6.0 一致，不导入 `bridge` 的项目行为不变；
- 依赖本框架的下游项目（例如基于它做预览的 IDEA 插件）目前锁定的是 1.5.1，上述迁移的影响会推迟到它们升级依赖版本时才出现，届时按 3.1 / 3.3 调整 import 即可。
